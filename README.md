# Зевс

Локальный голосовой ассистент для Windows. Слышит обращение «Зевс», выполняет команды на компьютере и отвечает через Ollama. Речь, поиск и запуск программ не уходят на чужой сервер: модели лежат на этой машине.

Текущая линия разработки — **v1.4**.

## Что нужно

- Windows 10 или новее
- Python 3.11+ (проект проверялся на 3.14)
- [Ollama](https://ollama.com/) с моделью `llama3.1`: `ollama pull llama3.1`
- Микрофон

Зависимости:

```bat
pip install -r requirements.txt
```

На Windows в список входят `pycaw` и `comtypes`: через них Зевс видит устройства Core Audio и ставит громкость системы.

## Запуск

Из корня проекта:

```bat
python main.py
```

Второе окно не откроется: один экземпляр держит мьютекс, чтобы две копии не дрались за микрофон и Vosk.

Голос по умолчанию спит, пока не услышит «Зевс». После фразы несколько секунд можно говорить уточнение без повторного обращения. Текстовый чат работает и в спящем режиме. Глобальная клавиша вызова — Ctrl+Alt+Space.

Журнал пишется в `data/zeus.log`. Его же можно открыть из интерфейса.

## Модели

Их нет в git, их кладут рядом с программой.

| Назначение | Куда положить |
|---|---|
| Распознавание «Зевс» и команд | `models/vosk-model-small-ru-0.22` |
| Голос Piper | `models/tts/voice.onnx` и `models/tts/voice.onnx.json` |

Русские голоса Piper: [rhasspy/piper-voices](https://huggingface.co/rhasspy/piper-voices/tree/main/ru). Для тона «Джарвиса» подходит `ru_RU-denis-medium`: скачанные файлы переименовываются в `voice.onnx` и `voice.onnx.json`. Подробности — в `models/tts/README.txt`.

Если Piper не найден, озвучка переходит на системный голос Windows (pyttsx3).

## Как проходит фраза

1. Микрофон, чат или трей отдают текст контроллеру (`src/core/controller.py`).
2. Пока агент ждёт подтверждения, «да» и «нет» относятся к этому действию. Другая фраза или «стоп» ожидание снимают.
3. Иначе диспетчер `router.call("run_command", ...)` вызывает `actions.execute_command`.
4. Системная команда уходит в одну из зон: запуск, медиа или поиск. Общие действия (открыть ссылку, запустить программу) живут в `src/core/command_effects.py` — их же вызывает агент.
5. Если команда не распознана, текст идёт в Ollama. При включённом агенте модель может вызвать инструменты.

Состояние одно на микрофон и голограмму: ожидание, слушаю, думаю, говорю, ошибка (`src/core/assistant_state.py`).

## Команды

Голос понимает, среди прочего:

- время, дату, калькулятор, заметки
- громкость и яркость
- «погугли …», погоду, поиск в Steam и на Taobao
- запуск и закрытие программ из `data/commands.json`
- поиск файла по индексу

База программ на новой машине создаётся из `data/commands.template.json` (пустые «приложения» и «игры»). Дальше её наполняет сканер рабочего стола и Steam. Служебные exe — установщики, `site-packages`, кэши `.vscode`, `.nuget`, `.codex` и похожие — в базу не попадают.

`data/commands.json` на рабочей машине содержит абсолютные пути установленных программ и не хранится в git. На другом компьютере пустой `commands.template.json` и сканер собирают свою базу.

## Агент

По умолчанию выключен. Тумблеры лежат в настройках, раздел модели:

| Настройка | По умолчанию | Что разрешает |
|---|---|---|
| `agent_enabled` | выкл | цикл инструментов вместо обычного ответа |
| `agent_allow_actions` | выкл | запуск, закрытие, ссылки, клики |
| `agent_allow_write` | выкл | запись файлов |

Поиск в сети и чтение файлов доступны, когда агент включён, даже без этих двух флагов. Системные папки закрыты deny-листом сканера.

Если действия или запись включены, Зевс не выполняет их молча: спрашивает «да» или «нет» в том же диалоге.

## Интерфейс

Живой экран — Neural Core: голограмма, статус, чат, терминал и настройки. Палитра общая для всех зон окна и лежит в `src/ui/shell_globals.py`.

Окно собрано из трёх частей:

| Файл | Зона |
|---|---|
| `src/ui/boot.py` | сплэш, трей, горячие клавиши, закрытие |
| `src/ui/layout.py` | сайдбар, главная, логи, настройки |
| `src/ui/handlers.py` | голос, чат, смена настроек и состояния |
| `src/ui/main_flet.py` | класс `ZeusUI`, который эти части соединяет |

## Каталоги

```
main.py                 запуск
src/core                контроллер, команды, агент, настройки
src/ui                  окно Flet
src/modules             микрофон, синтез, трей, погода, Taobao
data                    settings.json, commands.json, zeus.log
models                  Vosk и Piper (не в git)
assets                  иконка и hologram.webp
tests                   pytest
zeus.spec               сборка PyInstaller
build_release.bat       dist -> release\Zeus\v1.4
```

Команды разложены так:

| Файл | Зона |
|---|---|
| `src/core/actions.py` | решает, чья это фраза, и оставляет прежние имена |
| `src/core/actions_launch.py` | база команд, запуск и закрытие |
| `src/core/actions_media.py` | громкость, яркость, время, калькулятор, заметки |
| `src/core/actions_search.py` | интернет, погода, магазины, индекс, диски |

Импорт `from core import actions` по-прежнему работает.

## Проверки

```bat
python -m pytest tests -q
```

## Сборка

`build_release.bat` собирает exe через `zeus.spec` и кладёт его в `release\Zeus\v1.4`. Папки `data` и `models` копируются рядом с exe: модели в архив PyInstaller не зашиваются. Перед сборкой закройте уже запущенный `Zeus.exe`.

Пути к Vosk и данным Piper в spec ищутся по установленным пакетам, а не по жёсткому каталогу Python.
